# rosdep管理依赖项

承接ros2中的cmake而来，cmake是为了我们更好更快地构建出项目，但是每次对大型项目进行复刻时，cmake中众多庞大地依赖项让人非常头疼，一编译出现各种神秘报红，```rosdep```和```package.xml```的功能就此凸显出来

很多大型项目都有这个命令行：

```shell
rosdep install --from-paths src -y --ignore-src
```

## 一. rosdep到底是啥

```rosdep```是一种依赖关系管理实用程序，又被称为元包管理器，只负责根据它对系统和依赖关系了解到的规则去寻找适合目标平台安装的包，真正的安装动作由软件管理包来完成，它不但能应用于单个包还能应用到包的目录上（工作空间）

## 二. package.xml的内容

```package.xml```是```rosdep```查找依赖关系的文件，在我们构建包的过程中，该文件里面的依赖列表是我们手动添加的，而且尽量不要发生遗漏或者不正确，不然别人想去用```rosdep```查找并安装包依赖的时候，最后可能编译构建出你的项目

```package.xml```文件中的依赖项通常被称为：rosdep-keys，这些依赖项由包的创建着手动填充到```package.xml```文件中，并且应该是所需要任何非内置库和包的详尽列表

列举一些标签：

- ```<depend>```：

  此标签内的依赖项是那些在包构建时和运行时都要用的，对于cpp包来说，最保险的就是添加上这个标签

- ```<build_depend>```：

​	如果运行时用不到依赖，只在编译构建时需要相关依赖，可以用这个标签

​	这样的解释其实这个有点像为了动态库(?)

- ```<build_export_depend>```：

  如果你导出一个头文件，该头文件又包含来自一个依赖项的头文件，那么其他```<build_depend>```（构建依赖）于你的包的包也需要这个头文件

  这主要适用于头文件和CMake配置文件

- ```<exec_depend>```：

​	此标签声明了运行包时需要的共享库，可执行文件，py模块，启动脚本和其他文件的	依赖项

- ```<test_depend>```：

  此标签声明仅测试所需的依赖项，此处依赖项不应与```<build_depend>```，```<exec_depend>```或者```<depend>```指定的重复

## 三. rosdep如何工作

rosdep的工作原理是通过将中央索引检索到本地机器上，这样它每次运行时不用访问网络，在ubuntu上，其配置存储在```/ect/ros/rosdep/sources.list.d/20-default.list```，这个中央索引被称为```rosdistro```

rosdep就是使用```中央索引```来解析和安装ros包的依赖项，通过读取```package.xml```文件中的rosdep键，然后查找和安装相应的依赖包，使ros开发者能更方便地管理和构建项目

对于如何添加相关的键（依赖项）到```package.xml```

- 如果这个依赖项是基于ros的包，并且这个ros包已经发布到ros生态中，可以直接使用该包的名称
- 如果想依赖一个非ros的包，通常是系统依赖，需要找到特定库的键

这个其实工作的原理就是有点像字典：键在相关的中央索引中我才能去构建相关依赖，而rosdep（服务）就是通过package.xml（客户）给出的键，去通过中央索引找到键背后的包最后根据不同的操作系统的包管理器将其解析为相应的安装名称去安装

## 四. 如何使用rosdep工具

### 1. 安装rosdep

```shell
sudo apt install python3-rosdep
```

### 2. 操作

```shell
#第一次
sudo rosdep init
#每一次
rosdep update
```

```shell
rosdep install --from-paths src -y --ignore-src
```

从src目录中的ros包中查找依赖，但是忽略源码中的依赖，然后自动安装这些依赖

- --from-path src：依赖关系查找路径，指定解析package.xml文件以解析其键的路径（src）
- -y：依赖安装过程中的所以提示选项都选择yes
- --ignore-src：忽略安装依赖项，这个参数告诉rosdep在查找依赖时忽略src目录中的源代码，通常用于避免因源代码更改而引起的不必要的依赖
