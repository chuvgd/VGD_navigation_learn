导航的任务基本上分为：定位——感知——规划——控制——行为

- 定位：```localization```，通过传感器并进行观测获取整车位置姿态，这里不强调非常精细的姿态，一般这个姿态指的是云台yaw的姿态
  - 定位方面：一般利用```lio```算法，这里选择的是```point_lio```，输出的是车体上电位姿```(lidar_)odom```2车体现在的位姿```base_link```和速度（?），同时会保存一份```PCD点云地图```
  - 局限：就是只要是传感器，只要有噪声，只要是设计的观测器算法，就是会漂（

![](/home/ubuntu/VGD_navigation/nav_learn/nav_know/assets/2026-10-05_00-58.png)

- 重定位：一般的导航栈都分为——```map2odom2baselink```，重定位就是维护```map2odom```这段变化以修正定位的误差

  - ```map2odom```：初始一般置成```0 0 0 0 0 0(x y z r p y)```，后续通过重定位去维护，这里主流的重定位就是```ICP```及其衍生算法（局限就是需要在线建图）

  - 注意：这个只是补偿误差不一定是真实的```map2odom```

![](/home/ubuntu/VGD_navigation/nav_learn/nav_know/assets/2026-10-05_01-08_1.png)

- 感知：其实简单来说就是从机器人的视角来看哪些地方能走哪些不能走，一般就是高程分析和代价设计

  - 全局栅格地图：一般静态离线生成，或者在线建图生成

  - 全局/局部代价：全局代价直接由全局栅格代价设计而来，局部代价还需要实时的点云数据和分析并进行代价设计；全局代价一般是用于给出全局路径规划，局部代价一般用于精细化的局部规划和避障

    ![](/home/ubuntu/VGD_navigation/nav_learn/nav_know/assets/sp_nav2.png)

![](/home/ubuntu/VGD_navigation/nav_learn/nav_know/assets/sp_nav.png)

个人认为：感知是整个导航中最难的一部分，原因就是将一个2D导航任务变成有3D感知的2.5D导航，所以，对于相关3D感知的设计非常关键，一般3D感知用于局部代价地图相关（避障和一些跨越特殊地形），至于为什么不用于全局，主要是全局相关的代价地图是可以进行离线静态设计以规划出比赛场上想要的路线，但是局部相关结合了自身车和场上其他车的一些情况，是在线的，因而用到了感知（高德地图——全局代价和规划；人眼识别并前进——局部代价和跟随）

![](/home/ubuntu/VGD_navigation/nav_learn/nav_know/assets/sp_nav3.png)

- 规划：就是在代价地图下，给出起点和终点，怎么能够去往到目标点，一般规划说的是全局，也有局部规划，但是笔者认为局部规划更像是跟随，但是也是不分彼此了，就看每个人对此的理解
  - 全局规划：一般不考虑车的相关运动学约束（v,a等），只是一个搜索
  - 局部规划（跟随）：更像是结合车体建模，将各种车体信息作为约束，进行规划出一条适合车体进行运动的路径——更多时候局部规划放在控制器进行优化，但是也有直接全局路径优化即直接放在全局规划器中

![](/home/ubuntu/VGD_navigation/nav_learn/nav_know/assets/sp_nav5.png)

![](/home/ubuntu/VGD_navigation/nav_learn/nav_know/assets/2026-10-05_01-26.png)

- 控制：跟上输出的路径，一般输出就是速度给下位机进行解算，目前代码是```Pure Pursuit（PID）```，未来优化方向就是```MPC```，这里就是感觉到```MPC```是把局部路径优化和跟随结合到一起进行解决输出，比较优雅，但是具体是前端优化还是后段约束规划并输出，笔者能力有限尚未学习到那么多，还需后续跟进给出相关见解

- 行为：上层——大脑，负责具体比赛怎么完成各种任务；下层——小脑（承接导航），告诉具体怎么到达和到达过程中出现问题如何```recovery```
